## 5. 缺陷与处置

### 5.1 已修：`DIGEST_JSON_PATH` 默认空导致反馈学不到元数据

证据：默认配置下预览运行不落 `digest.json`；而 `scripts/feedback.py` / `scripts/feedback_server.py` 默认读 `digest.json` 解析论文标题与作者。本地用户按 README 跑预览后投票，`history` 拿不到 categories/authors，学习信号退化为纯作者/无。

修复：`arxiv_digest/config.py` 的 `digest_json_path` 默认改为 `"digest.json"`（仍可显式留空关闭）；`.env.example` 同步；新增回归 `test_default_digest_path_supports_feedback_metadata`。

### 5.2 未修（建议）：`background` / `verdict` 的数字回查失败会整段丢弃

证据：运行 #1 日志出现 `过滤评论中数字无法回查的字段：background` 与 `：verdict` 各一次。数值护栏本身是对的（防编造），但**整段置空**会让精读卡失去最显眼的"一句话结论"，读者只看到一张没有结论的卡。

建议：与 `advice_supported` 一致的降级策略——先尝试删去含不可核数字的分句/句子再复查；仍不过才置空，并在 report 里累计 `field_rejections` 计数供运维观察。

### 5.3 未修（记录）：期刊论文的反馈学不到分类

`feedback._remember` 只存 arXiv `categories`；`doi:` 论文 `categories=[]`。可考虑把 `pack_hint` / `venue` 作为弱分类写入 history（需同时在 `learned_weights` 与 `boost_for` 里定义匹配规则），否则期刊票只影响作者权重。属功能扩展，不属本轮缺陷修复。

### 5.4 本轮未能验证

- SMTP 实发与客户端渲染（未配置/未授权发信）。
- Zotero 库匹配与「读者已收藏」prompt 块（`ZOTERO_*` 为空）。
- 反馈端点（`FEEDBACK_URL` 为空；`scripts/feedback_server.py` 与 Apps Script 只在测试替身里验过契约）。
- GitHub Actions 云端执行、state 回写、缓存命中。
- 10 项 JS 契约（本机 PATH 无 `node`）。
